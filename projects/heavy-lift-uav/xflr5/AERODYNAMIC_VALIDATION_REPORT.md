# 🛩️ Aerodynamic Validation Report: Momentum Theory vs. BEM Sizing Rebuild

This report documents the validation of the heavy-lift UAV's **40" × 13" propeller** aerodynamics. It contrasts simplified **Actuator Disk (Momentum) Theory** against **Blade Element Momentum (BEM) Theory**, discusses the capabilities and boundaries of **XFLR5** and **QBlade**, and provides step-by-step instructions for manual 3D simulation validation.

---

## 1. Why Momentum Theory is a Simplification

In `projects/heavy-lift-uav/design_calculations/propulsion.py`, the required mechanical power is modeled using **Actuator Disk (Momentum) Theory**:

$$P_{\text{ideal}} = T \cdot v_i = T \cdot \sqrt{\frac{T}{2 \rho A}}$$

$$P_{\text{mechanical}} = \frac{P_{\text{ideal}}}{\eta_{\text{FoM}}}$$

While momentum theory is an excellent tool for preliminary sizing and convergence loops, it is a highly simplified model due to the following assumptions:

1. **Actuator Disk Approximation:** It treats the entire propeller plane as an infinitely thin, uniform pressure disk that experiences a homogeneous velocity change. It ignores the fact that thrust is generated by discrete, finite-span blades.
2. **Uniform Downwash:** It assumes the induced velocity $v_i$ is uniform across the entire disk area. In reality, downwash varies radially, peaking near the outer third of the blade and dropping to zero at the root (hub) and the tip.
3. **No Blade Geometry Integration:** It does not take into account the physical blade shape—specifically, how the **chord** (taper) and **twist** (pitch angle) vary from root to tip.
4. **No Viscous or Stall Modeling:** It summarizes all aerodynamic losses (profile drag, tip vortices, stall) into a single, static efficiency parameter: the **Figure of Merit ($\eta_{\text{FoM}}$)**. It cannot predict local flow separation or stall if the propeller operates outside its design range.

## 2. Tool Boundaries: XFLR5 vs. QBlade

When validating propeller aerodynamics, it is critical to understand why we transition between tools and their underlying physical formulations.

### Why XFLR5 Can Only Validate the 2D Airfoil (NACA 4412)
XFLR5 combines **XFOIL** (for 2D foil analysis) with 3D algorithms like the **Vortex Lattice Method (VLM)** and the **3D Panel Method**. However, XFLR5 is strictly a **fixed-wing solver**:
* **No Rotation Terms:** The equations of motion solved in XFLR5 assume a steady, uniform freestream velocity vector ($V_{\infty}$) relative to the aircraft. It does not include the rotational reference frame terms (Coriolis and centrifugal accelerations) required to model a spinning blade.
* **Foil Analysis Role:** We use XFLR5 solely to generate the 2D lift and drag polars ($C_l$ and $C_d$ vs. $\alpha$) for the **NACA 4412** airfoil. These polars are computed over the operating Reynolds number range ($Re \approx 35,000$ to $140,000$) to capture viscous skin friction and pressure drag. 

### Why QBlade is the Correct Next Tool
QBlade is a dedicated wind turbine and rotor aerodynamic solver. It implements **Blade Element Momentum (BEM) Theory**, which combines the physics of both worlds:
* **Discretized Radial Slices:** BEM divides the blade radially into multiple independent elements.
* **Local Inflow Vector:** For each element, it computes the local inflow angle ($\phi$) and relative velocity ($W$) as a function of both the vertical speed ($V_{\text{climb}}$) and the local rotational velocity ($V_{\theta} = \Omega \cdot r$).
* **Viscous Coupling:** It reads the XFOIL polars (generated in XFLR5) to determine the exact lift ($C_l$) and drag ($C_d$) generated by that specific element at its local angle of attack ($\alpha = \theta_{\text{local}} - \phi$).
* **Induction factors:** It solves for the axial ($a$) and angular ($a'$) induction factors iteratively at each element, capturing the radial downwash distribution.

## 3. Comparison: Custom BEM Solver vs. Momentum Theory

To cross-verify our design baseline, we compared our custom BEM solver (`simulation/rotor_bem.py`) using the exact geometric parameters from `propeller_40x13_blade.txt` against the momentum-theory equations in `propulsion.py` at the converged hover operating point:

* **Target Hover Thrust:** **56.53 N** ($5.76\text{ kg}$ lift per rotor)
* **Air Density:** $\rho = 1.225\text{ kg/m}^3$

### Comparison Results

| Parameter | Momentum Theory Baseline | Custom BEM Solver Prediction | % Difference |
| :--- | :---: | :---: | :---: |
| **Hover Rotor Speed** | 1,850 RPM (Fixed Input) | **1,737 RPM** (to match 56.53 N) | **-6.1%** |
| **Mechanical Power (per rotor)** | **495.5 W** (with 15% profile drag) | **551.7 W** | **+11.3%** |
| **Total Propulsion Power (6 rotors)** | **2,973.0 W** | **3,310.2 W** | **+11.3%** |

### Physical Interpretation of Results

1. **Lower Rotor Speed for Hover (1,737 RPM vs. 1,850 RPM):**
   The BEM solver predicts that the blade will generate the required 56.53 N of thrust at a slightly lower RPM than estimated. This occurs because the custom BEM solver uses the true, high-camber profile coordinates of the NACA 4412 along the entire span, which exhibits a higher lift-curve slope ($\approx 2\pi$) than the simplified quadratic thrust coefficient ($C_T$) fit used to estimate RPM in the power script.
2. **Higher Mechanical Power (+11.3%):**
   The BEM solver predicts that we need **11.3% more mechanical power** (551.7 W vs. 495.5 W per rotor) to hold hover. This difference is physically realistic:
   * **Momentum theory** accounts for profile drag as a simple flat 15% addition to the ideal power.
   * **BEM theory** computes the actual drag of each radial slice based on its local Reynolds number and angle of attack. Because the inner stations operate at very low Reynolds numbers ($Re \approx 35,000$), they experience significantly higher viscous drag coefficients ($C_d$). BEM captures these local losses, resulting in a more realistic, higher power prediction.

## 4. Manual QBlade Validation Tutorial

Since automated browser execution is restricted by environment limitations, you can perform the full 3D BEM simulation sweep manually in the QBlade GUI:

### Step 1: Download & Extract QBlade
1. Open your web browser and navigate to the official downloads page: **[qblade.org/downloads/](https://qblade.org/downloads/)**
2. Download the **QBlade Community Edition (QBlade-CE) for Linux (x64)**.
3. Extract the ZIP archive to your workspace:
   ```bash
   unzip QBladeCE_2.0.9.7_linux.zip -d qblade-ce
   ```

### Step 2: Install System Dependencies
Open your terminal and run the following command to install the required shared libraries:
```bash
sudo apt-get update
sudo apt-get install -y libqt5opengl5 libqt5xml5 libquadmath0 libglu1-mesa libssl-dev libgl1-mesa-glx libxcb-xinerama0 libxkbcommon-x11-0
```

### Step 3: Launch QBlade
Navigate to the extracted directory and run the wrapper script:
```bash
cd qblade-ce
chmod +x run_qblade.sh
./run_qblade.sh
```

### Step 4: Import Airfoil & Generate Polars
1. Go to **Airfoil Design ➔ Import Airfoil**.
2. Browse and select the coordinate file: `projects/heavy-lift-uav/xflr5/naca4412.dat`.
3. Select **Airfoil Analysis** from the menu.
4. Define a new polar analysis (Type 1 - Fixed Reynolds Number).
5. Generate polars for the following operating Reynolds numbers at angles of attack ($\alpha$) from $-5^\circ$ to $15^\circ$ (step $0.5^\circ$):
   * **35,000** (Root elements)
   * **90,000** (Mid-span elements)
   * **140,000** (Tip elements)

### Step 5: Define the Rotor Blade
1. Go to **Rotor / Turbine Design ➔ Blade Design**.
2. Create a new blade and set the type to **Rotor / Propeller**.
3. Set the number of blades to **2** and the outer radius to **0.508 m**.
4. Input the 10 radial stations from `projects/heavy-lift-uav/xflr5/propeller_40x13_blade.txt`:
   * Input the Radius (m), Chord (m), and Twist (deg) for each station.
   * Assign the corresponding `NACA4412` polar data to each station.
5. Save the blade definition.

### Step 6: Execute the BEM Sweep
1. Go to **Rotor / Turbine Analysis ➔ BEM Simulation**.
2. Set the **Freestream Velocity** to `0 m/s` (representing static hover).
3. Set the **Rotor Speed (RPM)** range to sweep from `1000` to `2600` in steps of `100`.
4. Click **Run Simulation**.
5. Export the generated curves to compare them directly against our custom BEM solver outputs.
